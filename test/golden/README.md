# Characterization Goldens — sp_engagement oracle

Goldens are **change detectors**, not correctness oracles. They encode the current
bash `sp_engagement` output for a fixed corpus, committed *before* any Rust
rewrite exists. Phase 2 (the Rust gate) must reproduce these byte-for-byte.

## Layout

```
test/golden/
  harness.sh         ── capture, diff, and batch-runner
  README.md          ── this file
  synthetic/         ── hand-crafted edge-case pads
    *.md               corpus (pad markdown with roster block)
    *.tsv              golden (captured oracle output)
  live/              ── real pad history from an archive.sqlite copy
    campaign-hub.md    corpus (never the live pad — copied out once)
    campaign-hub.tsv   golden
```

## Golden format

TSV with header: `seat` `since` `ordinal` `sender` `last_reply` `reply_target`

- **seat** — roster name the oracle was called for
- **since** — the cursor (ordinals ≤ since are skipped)
- **ordinal** — oldest unanswered mention's block number, or 0 if none
- **sender** — who authored that mention, or empty if ordinal=0
- **last_reply** — seat's most recent reply ordinal
- **reply_target** — who that last reply was addressed to

Generated by iterating every (seat, since) tuple for each corpus pad. The
sp_engagement awk program produces `"<ordinal> <sender> <last_reply>
<reply_target>"` per invocation; the harness splits and formats it into TSV.

## Usage

```sh
# Capture a golden (run once per corpus, commit the .tsv)
./test/golden/harness.sh capture test/golden/synthetic/deafness.md test/golden/synthetic/deafness.tsv

# Diff a single golden against current code
./test/golden/harness.sh diff test/golden/synthetic/deafness.md test/golden/synthetic/deafness.tsv

# Run all goldens (every .md with matching .tsv)
./test/golden/harness.sh all
```

`harness.sh` runs under `env -i` just like the rest of the suite: set
`STITCHPAD_HOME` to point at the tool directory.

## Synthetic corpus coverage

| File | What it exercises |
|---|---|
| `deafness.md` | Per-sender reply ledger: reply-to-one must not deafen the seat to later mentions from same sender (Regression 14) |
| `cross-sender.md` | Reply to X must not clear Y's unanswered mention |
| `fenced-code.md` | `` ```fenced``` `` and `` `backtick` `` `@mentions` must not wake |
| `silent-ack.md` | `.` / `[ack]` prefix and implicit word list (ack, noted, got it, etc.) silence agent-to-agent traffic |
| `broadcast.md` | `@all` broadcast reaches every roster member |
| `fifo-burst.md` | Five unanswered mentions in FIFO order — cursor steps, not jumps |
| `self-authored.md` | A seat mentioning itself is skipped |

## Live corpus

`live/campaign-hub.md` is the first 50 authored blocks from `campaign-hub-rust-rebuild`'s
`archive.sqlite`, copied out and **never touched again**. It provides real-world
pad text with 8 roster seats and ~600 total authored blocks.

## When a golden changes

A golden diff means the bash oracle's output changed — either a bug was fixed or
a regression was introduced. **Never re-bless the golden file to make a test pass.**

Instead:
1. Prove which side is right (the golden or the new output).
2. If the golden was encoding a bug: update it in the same commit that fixes the bug, with the red→green evidence.
3. If the code introduced a regression: fix the code, not the golden.

## Environment

The harness creates an ephemeral `.stitchpad` directory for `lib.sh` init and
cleans it up on exit. It never reads or writes any repository state.
